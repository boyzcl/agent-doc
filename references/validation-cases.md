# 自测用例

这个文件用于验证 `agent-doc` 的触发边界是否合适。

## Case 1：复杂项目文档混乱

场景：
- 仓库里同时有根 `AGENTS.md`、多个 handoff、`docs/`、archive、评测报告
- Agent 经常把实验记录当成当前规则
- 团队想直接重写全部文档并上全量检查

预期：
- `应该触发`

原因：
- 这是典型的入口问题、authority 问题、历史 / 证据混淆问题和范围失控问题叠加
- `agent-doc` 能提供最小入口层、authority map、bounded pilot 和轻量检查路径

推荐首轮动作：
1. 修根入口和 `docs/index.md`
2. 建 authority map
3. 拆出当前规则、历史背景、证据目录
4. 只治理一个高频流程

## Case 2：普通写文档

场景：
- 用户只需要写一篇新的 API 使用说明
- 仓库入口和 authority 已经明确
- 不涉及治理边界、历史目录或试点策略

预期：
- `不应过度触发`

原因：
- 这是单篇文档编写任务，不是文档系统治理任务
- 此时应直接使用已有模板或现有项目规范，而不是启动 `agent-doc` 的完整治理流程

推荐动作：
1. 直接沿用项目已有模板
2. 只检查该文档是否符合当前规则和路径
